# RIG — локальный AI на Acer

Основная модель: **Qwen2.5-Coder-7B-Instruct, GGUF Q4_K_M**, официальный
[источник Qwen](https://huggingface.co/Qwen/Qwen2.5-Coder-7B-Instruct-GGUF).
Исходная Qwen3.5-4B сохранена как профиль `general`.
Движок: [llama.cpp](https://github.com/ggml-org/llama.cpp), commit
`18b5f8b1862ebfe0f1c33d2355b81a54d2fec867`.

Настройка для i5-3337U / Debian 13: AVX и F16C, без AVX2/FMA/BMI2;
два потока, контекст 4096, один одновременный запрос, CPU без GPU offload.
Процесс имеет nice=10, чтобы рабочий стол получил приоритет.

## Использование

- **Super+Shift+A** или кнопка **AI** в Polybar — запустить и открыть терминальный чат во вкладке Kitty.
- В меню приложений — **RIG — локальный AI**.
- Открыть вручную из корня лаборатории: `python3 tools/local-ai/launch.py`.
- Дополнительный веб-интерфейс: `http://127.0.0.1:8087`.
- Правая кнопка на AI в Polybar — остановить модель.
- Остановка вручную: `python3 tools/local-ai/stop.py`.

Повторный запуск открывает новую вкладку в окне Kitty LAB AI. Команды чата: `/new` — очистить диалог, `/exit` — выйти, Ctrl+C — прервать ответ. Диалог хранится только в памяти процесса; история на диск не записывается. Веб-интерфейс можно открыть отдельно: `python3 tools/local-ai/launch.py --browser`.

Автозапуска при входе нет. После пяти минут без запросов llama-server выгружает
модель и её кеш из RAM. Следующий запрос загружает её снова. Это отличается от
полного выключения сервера: для полного освобождения процесса использовать Stop.

Ответы вычисляются на ноутбуке. Сервер слушает только loopback, не доступен
по LAN. Загрузка модели и инструментов требует интернета; последующий текстовый
инференс не требует внешнего API или API key. Автоматического исполнения команд
и подключения к Telegram у этого чата нет. Исходники Android-приложения не менялись.

Русский технический профиль задан в `system-prompt.txt` и `ui-config.json`.
Он просит краткие предметные ответы без нравоучений и лишних дисклеймеров.
Это инструкция поведения, а не изменение весов модели; отсутствие любых
отказов не гарантируется. Режим размышлений отключён для меньшей задержки.
В терминале начальный предел ответа — 512 токенов; `/tokens 1024` увеличивает его.
`/paste` включает многострочный ввод, отдельная строка `/end` завершает вставку.
В веб-интерфейсе предел — 512 токенов; настройки меняются в UI. Браузер может
сохранить историю и персональные настройки локально, серверный лог промптов не
включён. Для длинных диалогов начинать новый чат; окно контекста ограничено.

## Измерения

На этом ноутбуке Coder: около 1,7 токена/с, максимальный RSS 4792 МиБ
(4,7 ГиБ), максимум 79°C. Первый токен холодного запроса — 43 секунды;
со знакомым системным профилем и новой задачей — около 15 секунд.
Две синтетические задачи: Coder прошёл 9/12 проверок, Qwen3.5-4B — 7/12.
Обе модели ошиблись в сохранении исходных интервалов; Coder также сравнивал
значения через repr, что неверно для равных словарей с разным порядком ключей
и равных значений 1 / True / 1.0. Это ограниченный тест, не гарантия качества
на реальных проектах. Автоматического редактирования файлов у чата нет.

## Проверка и обслуживание

- Проверка файла: `python3 tools/local-ai/verify-model.py`.
- Тестовые ответы/память/температура: `python3 tools/local-ai/benchmark.py`,
  когда сервер запущен. Тест использует три синтетические задачи, не переписку.
- Журнал сервера: `tools/local-ai/runtime/server.log`.
- Результаты измерений: `tools/local-ai/runtime/benchmark.json`.
- Журнал сборки: `tools/local-ai/runtime/build.log`.
- Параметры запуска: `server.sh`.

Модель, виртуальное окружение, движок и runtime исключены из Git. Проверенные контрольные суммы всех частей моделей находятся в `models.json`.

Для повторной установки: `bash tools/local-ai/setup.sh`; нужен компилятор C/C++,
make, Python с venv, Git и curl. Инструменты CMake/Ninja ставятся в `.venv`,
системный Python не меняется. `setup.sh` не обновляет существующий checkout
движка автоматически. Ярлыки: `python3 tools/local-ai/install-launcher.py`;
скрипт сохраняет заменяемые настройки i3 и Polybar в `~/.config/rig-backups/`.

Локальный API для совместимых клиентов: `http://127.0.0.1:8087/v1`, модель
`rig-local`. Текущая конфигурация предназначена для текстового диалога;
визуальный проектор для картинок не скачан.

## Профили и проверка программирования

Официальный кандидат для кода: [Qwen2.5-Coder-7B-Instruct Q4_K_M](https://huggingface.co/Qwen/Qwen2.5-Coder-7B-Instruct-GGUF).
Метаданные двух частей и SHA-256 находятся в `models.json`. `active-model.json`
задаёт выбранный профиль. Команды переключения проверяют файлы перед запуском:

- `python3 tools/local-ai/launch.py --profile coder` — специализированный Coder.
- `python3 tools/local-ai/launch.py --profile general` — исходная Qwen3.5-4B.
- `python3 tools/local-ai/download-model.py coder` — скачать Coder и проверить SHA.
- `python3 tools/local-ai/benchmark.py --coding` — получить код для двух синтетических задач.
- `python3 tools/local-ai/check-coding.py` — проверить полученный код; запускать в sandbox,
  поскольку проверка исполняет сгенерированные функции.

Сравнение включает равные словари/списки, сохранение порядка, пустые входы,
пересечение/касание/вложенность интервалов и отсутствие изменения исходных данных.
У исходной Qwen3.5-4B обнаружены 5 ошибок на 12 проверках; у Coder — 3 на 12.
Отчёты и исходные ответы сохраняются только в исключённом из Git `runtime/`.
