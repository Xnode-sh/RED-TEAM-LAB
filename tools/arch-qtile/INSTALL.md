# Полная миграция RIG: Debian → Arch + Qtile X11

## Границы готовности

Это подготовленный комплект, не выполненная установка. Оператор прямо разрешил заменить Debian. Внешний носитель пока не предоставлен; установка не начинается до проверенной резервной копии. Данные только в GitHub не достаточны для восстановления: в домашнем каталоге около 11 ГБ, включая модели, Codex, настройки и credentials.

Сохраняем пользователя `red-team-lab`, UID 1000, путь `~/RED-TEAM-LAB` и роль RIG. Новая ОС не меняет идентичность агента. Переносим файлы, историю и настройки; работающий процесс этого чата через перезагрузку не переносится.

## Носители и резервная копия

Оператор располагает одной флешкой Silicon-Power 16 ГБ. Для этого подготовлен [маршрут Ventoy + миграционный архив на одном носителе](ONE-USB.md). Полный архив корня требует больше места; миграционный архив сохраняет весь домашний каталог без повторных downloads, /etc, /usr/local и /root. Флешку с единственной резервной копией нельзя затем перезаписывать raw-образом ISO.

1. ISO 2026.10.01 скачан в `tools/arch-qtile/downloads/archlinux-2026.10.01-x86_64.iso` (1 640 497 152 байт). SHA-256 `684ded26c63240ff4a41e8c25ee84ea6da233f557364821f13d12c2b0a9059a5` совпал с https://archlinux.org/download/ . GPG-подпись подтверждена ключом `3E80CA1A8B89F69CBA57D98A76A5EF9054449A5C`, fingerprint сверен с официальной страницей. ISO, подпись и keyring исключены из Git; флешка ещё не записана.
2. Скопировать этот комплект на внешний носитель. До перезагрузки завершить работу приложений и Codex, чтобы SQLite/история попали в согласованную офлайн-копию.
3. Загрузиться в Arch Live, определить диски заново через `lsblk -f` и `lsblk -o NAME,SIZE,MODEL,SERIAL`. Имена устройств могут измениться. Подключить сеть, проверить время.
4. Смонтировать подтверждённый раздел Debian в `/mnt/debian` только для чтения; внешний накопитель — в `/mnt/backup`. Проверить, что это разные физические диски.
5. Запустить `bash backup-live.sh /mnt/debian /mnt/backup` от root. Скрипт запрещает архивирование текущего корня, проверяет разные диски, свободное место, шифрует полный архив и проверяет его чтение. Пароль вводить только в локальном терминале и сохранить отдельно.
6. Проверить SHA256SUMS, расшифровать архив и выборочно извлечь проект, модель и файл истории в отдельный каталог внешнего диска. Сравнить их с оригиналом. Удаление Debian до этой проверки запрещено.

Бэкап включает домашние файлы и `/etc` с системными настройками/секретами. Не загружать его в публичный репозиторий. После миграции не восстанавливать Debian `/usr`, `/lib` или весь `/etc` поверх Arch.

## Предлагаемая разметка — ещё не применена

Для сохранения BIOS-загрузки: GPT с разделом BIOS boot 1 MiB (`bios_grub`), корень ext4 100 GiB, swap 16 GiB, домашний ext4 — оставшееся место. Если Live загружен в UEFI, потребуется другая схема загрузки с ESP; не применять BIOS-схему автоматически.

Перед разметкой снова сверить модель и серийный номер целевого HDD. Команды форматирования намеренно не автоматизированы. После подтверждения бэкапа заменить старую разметку, смонтировать новый корень `/mnt`, домашний каталог `/mnt/home`, подключить swap.

Установить базовую систему через `pacstrap`: base, linux-lts, linux-firmware, intel-ucode, grub, networkmanager, sudo, git, rsync, gnupg. Выполнить `genfstab`, `arch-chroot`, задать Europe/Kyiv, UTF-8 локали, hostname, пароль и пользователя UID 1000 с sudo. Установить GRUB для фактически выбранного BIOS/GPT или UEFI режима. Это ручной этап по актуальному Installation guide; подготовка файлов не заменяет его выполнение.

## Восстановление

В Live проверить `sha256sum -c SHA256SUMS` в каталоге бэкапа. Из расшифрованного архива извлечь **только** `./home/red-team-lab` в `/mnt` (корень нового Arch). Архив содержит путь `./home/red-team-lab`; не менять его наугад. Затем проверить владельца UID/GID нового пользователя и права приватных каталогов.

Восстанавливаются `.codex` (история, конфиг, skills/plugins и файловая авторизация), `.config` (в том числе Kitty, GitHub, Telegram), `.local`, проект целиком с `.git`, модели, документы, изображения и видео. ОС-keyring может потребовать повторного входа. Не выводить auth.json, hosts.yml и telegram.json. Локальные исполняемые файлы и Python venv от Debian не считать совместимыми с Arch без проверки.

После первого запуска Arch:

```bash
sudo bash ~/RED-TEAM-LAB/tools/arch-qtile/install-system.sh
bash ~/RED-TEAM-LAB/tools/arch-qtile/install-user.sh
```

Системный скрипт отказывается работать на Debian/Live, не меняет разметку. Пользовательский сохраняет заменяемые конфиги в `~/.config/rig-backups/`, устанавливает Qtile/Kitty-конфиги и Codex 0.160.1, соответствующий наблюдаемой текущей версии. Исходный kitty.conf сохраняется. В LightDM выбрать сессию Qtile X11.

## Драйверы этого Acer

| Устройство | Подтверждённый текущий драйвер / выбор для первого запуска |
| --- | --- |
| Intel HD 4000 | i915 из ядра + Mesa, Xorg modesetting; libva-intel-driver для старого Intel VA-API |
| NVIDIA GT 740M / GK208M | nouveau из ядра + Mesa; обычные nvidia/nvidia-open не подходят этой Kepler |
| Wi-Fi Atheros AR9565 | ath9k из ядра; NetworkManager управляет соединением |
| Broadcom BCM57786 Ethernet | tg3 из ядра, не broadcom-wl |
| Intel HDA | snd_hda_intel из ядра; PipeWire + WirePlumber |
| SATA / USB / SD | ahci / xhci_hcd, ehci-pci / sdhci-pci из ядра |
| Intel CPU | intel-ucode; после загрузки проверить microcode и сообщения ядра |

Базовый графический сеанс проверять на Intel. NVIDIA и сон проверяются отдельно; наличие пакета не доказывает исправность устройства. Проприетарный legacy-драйвер не устанавливается автоматически.

## Локальный AI и захват экрана

- Сохранить GGUF и models.json, выполнить `verify-model.py` для general/coder.
- Выполнить `bash tools/arch-qtile/build-ai.sh`: проверяются модели и сохранённая ревизия llama.cpp, старый build переименовывается в резервный, новый собирается системными cmake/ninja Arch. Сборка AVX/F16C, AVX2/FMA/BMI2 отключены, два потока. Debian `.venv` не используется. Сборка и работа модели проверяются на фактически установленном Arch.
- Захват экрана на Arch использует системный FFmpeg: `RIG_CAPTURE_SYSTEM_FFMPEG=1`. Не подмешивать Debian-библиотеки в Arch. Конфиг Qtile задаёт эту переменную для autostart и дочерних команд.
- Исправлен launcher AI: отсутствие i3 больше не ломает открытие второй вкладки Kitty.

## Проверки приёмки

1. Перезагрузка с HDD, выбранное ядро, microcode, отсутствие ошибок загрузки.
2. Qtile X11: терминал, EN/RU, раскладки, яркость, панель, звук, Wi-Fi и Ethernet.
3. Сон/пробуждение, питание, тачпад, SD-карта и NVIDIA по фактическим устройствам.
4. `~/.local/bin/codex --version`, `codex login status`, `codex resume` из проекта. Если требуется, войти через официальный `codex login`; не передавать токены в чат.
5. Проект и `.git` на месте, models.json SHA-256 совпали, локальный AI отвечает в Kitty.
6. PNG и короткая запись с системным звуком, проверка FFprobe, видимый индикатор REC.
