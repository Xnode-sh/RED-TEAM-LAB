# Handoff Protocol

Единый протокол передачи задачи между инженерами RED └•TEAM•┐ lab™.
Каждый инженер (RIG, KAI, NOVA, ORBIT) умеет передавать работу другому.

Часть общей [системы совместной работы](COLLABORATION.md). Допустимые направления
передачи — см. [DEPENDENCIES.md](DEPENDENCIES.md). Блокировки файлов — [LOCKS.md](LOCKS.md).

## Стандарт записи

Каждая передача оформляется записью фиксированного формата:

```text
FROM:       <агент, передающий работу>
TO:         <агент, принимающий работу>
TASK:       <ID из TASKS.md + краткое описание>
STATUS:     <pending | active | blocked | done>
BLOCKERS:   <что мешает продолжить, или "нет">
FILES:      <затронутые файлы/пути>
NEXT STEP:  <конкретное следующее действие для принимающего>
TIMESTAMP:  <YYYY-MM-DD HH:MM UTC>
```

## Правила

1. Передача разрешена только в направлениях, описанных в [DEPENDENCIES.md](DEPENDENCIES.md).
2. Запись публикуется в описании PR или Issue и дублируется строкой-ссылкой в [TASKS.md](TASKS.md) (поле «Передана кому»).
3. Все перечисленные в `FILES` пути должны быть освобождены передающим в [LOCKS.md](LOCKS.md); принимающий при необходимости берёт их заново.
4. `NEXT STEP` обязателен и должен быть выполнимым без устного контекста.
5. Передача не изменяет роли и зоны: принимающий работает в своей зоне и ветке.
6. Секреты в запись не включать (см. [../SECURITY.md](../SECURITY.md)); только пути и факты.

## Пример

```text
FROM:       KAI
TO:         ORBIT
TASK:       T-004 — интеграция системы совместной работы
STATUS:     active
BLOCKERS:   нет
FILES:      docs/COLLABORATION.md, scripts/validate_pr.py
NEXT STEP:  провести review PR и подготовить merge после разрешения оператора
TIMESTAMP:  2026-10-06 15:10 UTC
```
