# Context Recovery (протокол старта)

После запуска агент обязан автоматически восстановить рабочий контекст, прежде чем
приступать к работе. Часть [системы совместной работы](COLLABORATION.md).

Этот документ формализует и расширяет раздел «Начало сессии» в
[AGENTS.md](../AGENTS.md); он ничего там не меняет, а ссылается на него.

## Последовательность чтения

Строго по порядку (единый протокол старта):

```
AGENTS.md
  → agents/<NAME>/ROLE.md
    → agents/<NAME>/STATE.md
      → agents/<NAME>/MEMORY.md
        → agents/<NAME>/SYNC.md
```

Дополнительно читаются общие документы: [TEAM.md](../TEAM.md),
[WORKFLOW.md](../WORKFLOW.md), [SECURITY.md](../SECURITY.md), [HQ.md](HQ.md),
а также текущая [очередь задач](TASKS.md), [зависимости](DEPENDENCIES.md) и
[блокировки файлов](LOCKS.md).

## Обязательный краткий отчёт

После чтения агент обязан вывести отчёт фиксированного формата (и только потом
начинать работу):

```text
MISSION:       <постоянная миссия агента из ROLE.md>
CURRENT TASK:  <активная задача из TASKS.md/SYNC.md или "нет">
LAST ACTION:   <последнее завершённое действие из STATE.md/SYNC.md>
BLOCKERS:      <известные блокеры из SYNC.md или "нет">
NEXT STEP:     <конкретный следующий шаг>
```

## Правила

1. Сохранённые сведения не доказывают текущее состояние среды — факты подтверждать заново (`git status`, ветка, HEAD, origin).
2. Идентичность определяется фактической средой (см. [AGENTS.md](../AGENTS.md)); чужую идентичность не присваивать.
3. Отчёт строится только на прочитанных файлах и проверенных фактах; предположения помечать как предположения.
