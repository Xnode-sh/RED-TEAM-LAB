# Session Checkpoint

Механизм сохранения контрольной точки после завершения каждой задачи.
Часть [системы совместной работы](COLLABORATION.md).

После завершения задачи агент обновляет три файла своей зоны — **без дублирования
информации** между ними:

| Файл | Что фиксирует | Что НЕ дублировать |
| --- | --- | --- |
| `agents/<NAME>/STATE.md` | Текущее состояние: активная задача, следующий шаг, состояние среды | Не копировать историю из MEMORY.md |
| `agents/<NAME>/MEMORY.md` | Устойчивые проверенные факты и уроки + строка в «История задач» | Не копировать оперативный статус из STATE/SYNC |
| `agents/<NAME>/SYNC.md` | Координационный статус: миссия, последняя задача, следующий шаг, блокеры, зависимости, время, commit, branch, PR | Не копировать уроки из MEMORY.md |

## Процедура

1. Обновить `SYNC.md`: последняя завершённая задача, следующий шаг, блокеры, время, `Commit SHA`, `Branch`, `PR`.
2. Обновить `STATE.md`: активная задача/следующий шаг по проверенным фактам.
3. Добавить в `MEMORY.md` одну строку в «История задач» (и урок, если он есть и проверен).
4. Перевести задачу в [TASKS.md](TASKS.md) в статус `done` (или `blocked`/`active`).
5. Снять свои блокировки в [LOCKS.md](LOCKS.md).
6. Прогнать [validation](../scripts/validate_pr.py) перед PR.

## Принцип отсутствия дублей

Один факт хранится в одном месте. Если сведение относится к нескольким файлам —
оно записывается в наиболее специфичный, а остальные **ссылаются** на него, а не
копируют. Повтор одного и того же текста в STATE/MEMORY/SYNC запрещён.
