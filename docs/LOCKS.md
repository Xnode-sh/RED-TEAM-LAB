# Conflict Prevention (блокировки файлов)

Запрещает ситуацию, когда два инженера одновременно изменяют один файл.
Часть [системы совместной работы](COLLABORATION.md).

## Принцип

Перед изменением файла агент проверяет реестр ниже. Если файл **уже занят** другим
агентом, агент обязан сообщить:

```text
FILE LOCKED
FILE:     <путь>
OWNER:    <агент, держащий блокировку>
SINCE:    <YYYY-MM-DD HH:MM UTC>
PROPOSAL: handoff — см. HANDOFF.md
```

и предложить передачу работы по [Handoff Protocol](HANDOFF.md), а не менять файл.

## Реестр блокировок

Активная блокировка = одна строка. Снятие = перевод в `released` или удаление
строки владельцем при [Session Checkpoint](CHECKPOINT.md).

| Файл / путь | Владелец | Статус | С какого времени (UTC) | Задача |
| --- | --- | --- | --- | --- |
| _(нет активных блокировок)_ | — | — | — | — |

## Правила

1. Блокировка берётся только на файлы своей зоны ([PROJECT_MAP.md](PROJECT_MAP.md)) или по согласованию.
2. Границей блокировки является файл; на каталог блокировка не берётся.
3. Блокировка снимается сразу после завершения работы (не держать «про запас»).
4. Разные файлы разными агентами параллельно — разрешено; один файл двумя — запрещено.
5. Git остаётся источником истины: реестр предотвращает конфликт заранее, но не заменяет review diff в PR.
